# Traçabilité d'architecture — Architecture et interfaces d'appel de Scobelix

Ce document trace chaque exigence de [../specification-fonctionnelle/architecture.md](../specification-fonctionnelle/architecture.md) vers son implémentation dans le code du dépôt Scobelix : fichier, fonction, et explication concise du mécanisme effectif. Les sections suivent l'ordre du document source ; les chemins sont relatifs à la racine du dépôt. Quand une exigence ne correspond à aucun code précis, cela est dit explicitement.

## 1. Vue d'ensemble et nature du système

| Exigence | Fichier — Fonction/élément | Explication |
|---|---|---|
| **FR-ARCH-01** : bibliothèque importable et commande, sans serveur | `scobelix/decompiler.py` — `decompile_bytecode()`, `decompile_address()` ; `scobelix/__main__.py` — `main()` | Les capacités sont de simples fonctions Python ; la commande n'est qu'un analyseur d'arguments qui les appelle. Aucun module du paquet n'ouvre de socket d'écoute, ne définit de route ni n'utilise de base de données serveur ou de file de messages (la base de signatures est un fichier SQLite local ouvert en lecture seule). |
| **FR-ARCH-02** : exécution synchrone, dans le processus et le fil de l'appelant, compilateur en processus fils | `scobelix/decompiler.py` — `_decompile_with_loader()` ; `scobelix/verify/solc.py` — `binary_version()`, `_standard_json_output()` ; `scobelix/solgen/validate.py` — `validate_solidity()` | Toutes les étapes s'enchaînent séquentiellement dans l'appel ; aucun fil n'est créé (`threading` ne sert qu'à des verrous et, dans `scobelix/__main__.py`, à reconnaître le fil principal) et le budget par fonction, comme l'interruption de la génération par le budget global, s'appuie sur un signal ; les seuls processus fils sont les `subprocess.run()` du compilateur (`--version`, `--standard-json`, `--bin`), dont l'appelant attend la fin. Les machines EVM s'exécutent dans le processus. |
| **FR-ARCH-03** : aucun accès réseau hors lecture du code d'une adresse et téléchargement autorisé du compilateur | `scobelix/loader.py` — `Loader.load_addr()` ; `scobelix/verify/solc.py` — `download_allowed()`, `download_solc()`, `available_releases()`, `_http_get()` ; `scobelix/utils/sigdb.py` | `load_addr()` est le seul endroit qui appelle `w3.eth.get_code()` ; `_http_get()`, seul autre accès réseau, n'est atteint que par `download_solc()` et `available_releases()`, appelés par `find_solc()` et `solc_for_source()` seulement si `download_allowed()` est vrai ; la base de signatures n'est qu'un fichier local (« Lookups never touch the network »). |
| **FR-ARCH-04** : bytecode runtime, bloc de métadonnées lu comme donnée, création non distinguée | `scobelix/loader.py` — `Loader.load_binary()` ; `scobelix/utils/metadata.py` — `parse_metadata()` | `load_binary()` convertit l'entrée en octets, lit le bloc final par `parse_metadata()` et ne désassemble que jusqu'à son début (`code_len = self.metadata.start`), sans autre analyse de structure : un bytecode de création est désassemblé et exécuté depuis la position 0 comme n'importe quel code. |
| **FR-ARCH-05** : en-tête hérité `# Palkeoramix decompiler. ` | `scobelix/decompiler.py` — `_decompile_with_loader()` | Première instruction du bloc `redirect_stdout` : `print(C.gray + "# Palkeoramix decompiler. " + C.end)`. |
| **FR-ARCH-06** : résultat en neuf parties | `scobelix/decompiler.py` — classe `Decompilation` | Dataclass à neuf champs `text`, `asm`, `json`, `proxy_hints`, `bytecode`, `metadata`, `dispatcher`, `functions`, `time_budget`, tous remplis par `_decompile_with_loader()` dans le même appel (`time_budget=budget`, `None` sans budget global). Vérifié en bac à sable. |

## 2. Capacités (points d'entrée fonctionnels)

| Exigence | Fichier — Fonction/élément | Explication |
|---|---|---|
| **FR-ARCH-07** : décompilation d'un bytecode hexadécimal, entrée invalide refusée | `scobelix/decompiler.py` — `decompile_bytecode()` ; `scobelix/loader.py` — `parse_hex_code()`, `InvalidBytecode`, `Loader.load_binary()` | `parse_hex_code()` accepte des octets tels quels, retire les espaces de bord (`strip()`) et un préfixe `0x` ou `0X`, puis lève `InvalidBytecode` pour un caractère hors de `_HEX_DIGITS` (avec sa position), un nombre impair de chiffres ou une valeur qui n'est pas une chaîne ; `load_binary()` l'appelle avant tout désassemblage. Vérifié en bac à sable (`zz`, `0x123`, `60 00`, `5` refusés ; `0X6000`, ` 6000\n` et des octets acceptés) ; couvert par `tests/test_loader_input.py`. |
| **FR-ARCH-08** : décompilation d'une adresse | `scobelix/decompiler.py` — `decompile_address()` ; `scobelix/loader.py` — `Loader.load_addr()` | `load_addr()` récupère le code puis appelle `self.load_binary(code)` ; la suite est strictement la même fonction `_decompile_with_loader()`. |
| **FR-ARCH-09** : filtre par préfixe de nom, fonctions ignorées hors échecs | `scobelix/decompiler.py` — `_decompile_with_loader()` ; `scobelix/loader.py` — `Loader.run()` | `Loader.run()` remplit `func_list` des fonctions de sélecteur, de `_fallback` et de `_receive` ; dans la boucle sur `loader.func_list`, `if only_func_name is not None and not fname.startswith(only_func_name): continue` saute la fonction avant le bloc `try`, donc sans l'ajouter à `problems`. Vérifié en bac à sable : `tr` ne garde que `transfer`, `zzz` aucune fonction, `problems` vide. |
| **FR-ARCH-10** : génération Solidity depuis la décompilation, mode dégradé sur l'AST | `scobelix/solgen/__init__.py` — `generate_solidity()` ; `scobelix/solgen/v2.py` — `generate()`, `Generator` | `generate_solidity()` délègue à `generate()`, qui lit les fonctions en mémoire (`orig_trace`), `bytecode`, `metadata` et `dispatcher` ; un objet sans fonctions en mémoire, ou le dictionnaire `json`, est relevé depuis les traces JSON avec les avertissements `no in-memory functions: lifted from the JSON traces (degraded)` et `no bytecode in the decompilation: …`. Vérifié en bac à sable. |
| **FR-ARCH-11** : validation par un compilateur externe, statuts, pipeline IR | `scobelix/solgen/validate.py` — `validate_solidity()`, `ValidationResult` | Le champ `status` ne prend que `valid`, `invalid` ou `skipped` ; sur `tack too deep` avec solc 0.8.13 ou plus récent, une seconde compilation `--via-ir --optimize` qui réussit donne `valid`, `via_ir = True` et `VIA_IR_ONLY` en premier avertissement. |
| **FR-ARCH-12** : capacité de vérification L0 à L4 | `scobelix/verify/core.py` — `verify()` ; `scobelix/verify/__init__.py` | `verify()` compile (L0), compare l'ABI (L1), la disposition du stockage (L2), exécute les deux codes côte à côte (L3) et compare les bytecodes (L4), puis renvoie un `VerificationReport` ; la génération l'appelle par `scobelix/solgen/tiers.py` — `search()`. |
| **FR-ARCH-13** : outil satellite de régénération des signatures | `scobelix/tools/build_local_sigs.py` — `main()` | Module autonome exécuté par `python -m` ; il n'est importé par aucun autre module du paquet. |
| **FR-ARCH-14** : bytecode vide ou réduit aux métadonnées, résultat « aucun code », état du budget global transmis | `scobelix/decompiler.py` — `_decompile_with_loader()` | Après la passe légère, `if len(loader.lines) == 0: return Decompilation(text=…, bytecode=loader.bytecode, metadata=metadata, time_budget=budget)` : `asm`, `json`, `proxy_hints` et `functions` gardent leurs valeurs vides par défaut, `dispatcher` vaut `None`, et `time_budget` le budget démarré en tête (`None` sans budget global), dont `exhausted` reste faux et `skipped` vide, rien ne les touchant avant ce retour. Vérifié en bac à sable avec `""`, `"0x"` et le seul bloc de métadonnées de `SimpleToken` (métadonnées renseignées). Couvert par `tests/test_time_budget.py` (`test_a_bytecode_without_code_keeps_the_state_of_its_budget` : `"0x"` et `""` sous 10 s → `seconds` 10, `exhausted` faux, `skipped` vide, `None` sans budget ; la commande `--combined-json --time-budget 10 0x` imprime `"time_budget": {"seconds": 10.0, "exhausted": false, "skipped": []}`). |

## 3. Pipeline de décompilation (vue d'ensemble)

| Exigence | Fichier — Fonction/élément | Explication |
|---|---|---|
| **FR-ARCH-15** : ordre des étapes | `scobelix/decompiler.py` — `_decompile_with_loader()` ; `scobelix/loader.py` — `Loader.load_binary()`, `Loader.run()` ; `scobelix/contract.py` — `Contract.postprocess()` | `load_binary()` (métadonnées, désassemblage) → `loader.run(VM(loader, just_fdests=True))`, qui appelle `dispatcher.analyse()` → par fonction `VM(loader).run()`, `make_whiles()` puis `Function(hash, trace, …)` (caractérisation) → `Contract.postprocess()` : `sparser.rewrite_functions()`, remplacement `cd` → `param`, liste des constantes, `make_asts()` → `detect_proxy_slots()` → `contract.json()` → rendu texte. |
| **FR-ARCH-16** : décompilation indépendante, échec isolé et journalisé | `scobelix/decompiler.py` — `_decompile_with_loader()` | Le corps de chaque fonction est dans `try … except (Exception, TimeoutInterrupt)` qui fait `problems[hash] = fname` et `logger.exception("Problem with %s%s", …)`, puis la boucle continue ; la construction de chaque `Function` est protégée de la même façon ; `Contract(problems=…, functions=…)` est construit ensuite quoi qu'il arrive. |
| **FR-ARCH-17** : reconstruction du stockage une seule fois pour le contrat | `scobelix/contract.py` — `Contract.postprocess()` | Un unique appel `sparser.rewrite_functions(self.functions)` reçoit la liste de toutes les fonctions décompilées. |
| **FR-ARCH-18** : slots de proxy détectés sur le seul désassemblage brut | `scobelix/decompiler.py` — `_decompile_with_loader()` ; `scobelix/utils/proxy_detect.py` — `detect_proxy_slots()` | `detect_proxy_slots(loader.parsed_lines)` ne reçoit que les triplets bruts produits par `load_binary()`, indépendamment des traces. |
| **FR-ARCH-19** : AST et texte dans la même passe, AST non plié, texte plié | `scobelix/function.py` — `Function.serialize()`, `Function._print()` ; `scobelix/contract.py` — `Contract.make_ast()` | `serialize()` sérialise `self.trace` (non plié) ; `_print()` rend `self.ast`, que `make_ast()` calcule à partir de `folder.fold(trace)`. Les deux sont appelés sur les mêmes objets `Function` dans `_decompile_with_loader()`. |

## 4. Configuration

| Exigence | Fichier — Fonction/élément | Explication |
|---|---|---|
| **FR-ARCH-20** : variables `PANORAMIX_*` lues une seule fois au chargement, `SCOBELIX_TIME_BUDGET` lue à chaque invocation de la commande | `scobelix/decompiler.py` — constantes `FUNCTION_TIMEOUT`, `VM_RUN_TIMEOUT`, `WHILES_TIMEOUT` ; `scobelix/loader.py` — `LOADER_TIMEOUT` ; `scobelix/vm.py` — `MAX_NODE_COUNT` ; `scobelix/__main__.py` — `parse_args()`, `_time_budget_from_environment()` | Les cinq valeurs sont calculées par `int(os.environ.get(…))` au niveau module, lors du premier import ; aucun code ne relit l'environnement ensuite. `SCOBELIX_TIME_BUDGET` (`TIME_BUDGET_ENV`) n'est lue que par `_time_budget_from_environment()`, que `parse_args()` appelle à chaque invocation lorsque `--time-budget` est absente ; `scobelix/decompiler.py` ne la lit pas (`time_budget` y est un paramètre). Couvert par `tests/test_time_budget.py` (`monkeypatch.setenv` sans rechargement de module). |
| **FR-ARCH-21** : budget par fonction (720 s) couvrant exécution symbolique, structuration et simplification, ramené par le budget global | `scobelix/decompiler.py` — `dec()` dans `_decompile_with_loader()`, `_capped()` | `@timeout_decorator.timeout(ft, timeout_exception=TimeoutInterrupt)` décore la fonction imbriquée qui appelle `VM(loader).run()` puis `make_whiles()` ; `ft = FUNCTION_TIMEOUT` (défaut `60 * 12`) sans budget global, `ft = min(_capped(FUNCTION_TIMEOUT, left), MAX_ALARM_SECONDS)` sinon, `left` étant `budget.left_for_functions(began)`, lu une fois avant la fonction (plafond : FR-ARCH-78). La construction de l'objet `Function` est hors de ce budget. |
| **FR-ARCH-22** : budget de l'exécution symbolique (600 s) ; sous budget global, sa part du budget de la fonction, qui s'achève avant l'alarme de la fonction | `scobelix/decompiler.py` — `dec()`, `_vm_share()`, `_capped()`, `SIMPLIFY_RESERVE` ; `scobelix/vm.py` — `VM.run()` | `VM(loader).run(target, stack=stack, timeout=vm_timeout, memory=memory)`, avec `vm_timeout = VM_RUN_TIMEOUT` sans budget global et `_vm_share(ft)` sinon : `ft * min(1.0, VM_RUN_TIMEOUT / FUNCTION_TIMEOUT)` lorsque les deux sont positifs, `_capped(VM_RUN_TIMEOUT, ft * (1 - SIMPLIFY_RESERVE))` sinon ; `should_quit()` compare `time.monotonic() - time_start` au budget, et une exécution qui l'atteint garde sa trace partielle (FR-DEC-30) au lieu d'être interrompue par l'alarme de `dec()`. Couvert par `tests/test_time_budget.py` (`test_under_a_budget_every_step_is_capped_by_what_is_left` : fonction de 90 s → exécution symbolique de 75 s ; `test_a_step_without_a_limit_of_its_own_gets_what_is_left`). |
| **FR-ARCH-23** : arrêt de la simplification à la plus proche des deux échéances, fonction exacte et marquée | `scobelix/decompiler.py` — `simplification_deadline()`, `SIMPLIFY_RESERVE`, `dec()` ; `scobelix/whiles.py` — `make_whiles()` ; `scobelix/simplify.py` — `simplify_trace()`, `last_run_timed_out` | `dec()` passe `timeout=WHILES_TIMEOUT` et `deadline=simplification_deadline(started)` (`started + FUNCTION_TIMEOUT * (1 - SIMPLIFY_RESERVE)`, `SIMPLIFY_RESERVE = 0.25`), ou, sous un budget global, `simplification_deadline(started, budget=ft)` (`started + ft * (1 - SIMPLIFY_RESERVE)`) ; `simplify_trace()` retient la plus proche (`_deadline = min(limits)`), que `_out_of_time()` consulte aussi à l'intérieur des réécritures quadratiques ; si `last_run_timed_out`, la fonction est ajoutée à `time_limited` puis `Function.time_limited = True`, sans entrer dans `problems`. Couvert par `tests/test_simplify_time_limit.py` et, sous budget global, par `tests/test_time_budget.py` (`test_the_simplification_deadline_follows_the_capped_function_budget`, `test_a_function_with_little_time_left_stays_exact_instead_of_failing`). |
| **FR-ARCH-24** : budget de la découverte (120 s), ramené par le budget global | `scobelix/loader.py` — `Loader.run()` ; `scobelix/decompiler.py` — `_decompile_with_loader()` | `vm.run(0, timeout=timeout)`, avec `timeout = LOADER_TIMEOUT` sans budget global ; sous budget, `_decompile_with_loader()` appelle `loader.run(…, budget=max(budget.left_for_functions(), MIN_SLICE))` et `Loader.run()` retient `min(LOADER_TIMEOUT, budget)`. |
| **FR-ARCH-25** : valeur nulle = pas de limite de temps, échéance de 75 % comprise, sauf sous un budget global | `scobelix/vm.py` — `VM.run()` ; `scobelix/simplify.py` — `simplify_trace()` ; `scobelix/decompiler.py` — `dec()`, `simplification_deadline()`, `_capped()` ; `scobelix/loader.py` — `Loader.run()` | `should_quit()` de la VM évalue `timeout and (…)`, faux pour 0 ; `simplify_trace()` n'ajoute `start + timeout` que si `timeout` est non nul ; `simplification_deadline()` renvoie `None` si sa limite (`FUNCTION_TIMEOUT`, ou `budget` lorsqu'il est donné) est `<= 0` ; pour le budget par fonction, la bibliothèque `timeout_decorator` n'arme aucune alarme lorsque le nombre de secondes est nul (comportement de la dépendance). Sous un budget global, `_capped(limit, cap)` rend `cap` pour une limite `<= 0`, et `Loader.run()` retient `budget` lorsque `LOADER_TIMEOUT <= 0` : la découverte et la fonction reçoivent le temps restant, `simplification_deadline(started, budget=ft)` une limite positive, et `_vm_share(ft)` 75 % de `ft` (au plus `VM_RUN_TIMEOUT` lorsqu'il est positif) dès que `FUNCTION_TIMEOUT` ou `VM_RUN_TIMEOUT` est nul. Couvert par `tests/test_time_budget.py` (`test_a_step_without_a_limit_of_its_own_gets_what_is_left`). |
| **FR-ARCH-78** : budget de temps global facultatif : option, variable lue à chaque invocation, valeurs refusées, très grandes valeurs plafonnées, paramètre de l'interface Python, budget entier par entrée | `scobelix/__main__.py` — `parse_args()`, `_time_budget_from_environment()`, `TIME_BUDGET_ENV`, `_seconds()`, `print_decompilation()`, `_generate_under_budget()` ; `scobelix/decompiler.py` — `decompile_bytecode()`, `decompile_address()`, `_decompile_with_loader()`, `TimeBudget.start()`, `MAX_ALARM_SECONDS` | `--time-budget` passe par `_seconds()` (`float()`, puis `0 < seconds < float("inf")`, faux pour `nan`) ; lorsque l'option est absente, `parse_args()` appelle `_time_budget_from_environment()`, qui lit `os.environ.get(TIME_BUDGET_ENV, "").strip()`, rend `None` pour une valeur vide et appelle `parser.error(f"{TIME_BUDGET_ENV}: {e}")` (code 2) pour une valeur refusée par `_seconds()` ; `print_decompilation()` transmet `time_budget=args.time_budget` à `decompile_address()` ou `decompile_bytecode()` pour chaque entrée ; `_decompile_with_loader()` appelle `TimeBudget.start(time_budget)` en tête, donc après `load_binary()` ou `load_addr()`, et `start()` lève `ValueError` pour une valeur qui n'est pas un `int` ou un `float` strictement positif et fini, ou qui est un booléen (`isinstance(seconds, bool)`). Une valeur aussi grande soit-elle est acceptée : les deux alarmes armées sous budget sont plafonnées à `MAX_ALARM_SECONDS = 1e9`, celle de chaque fonction par `ft = min(…, MAX_ALARM_SECONDS)` dans `_decompile_with_loader()` et celle de la génération par `time_left = min(budget.remaining() - OUTPUT_RESERVE, MAX_ALARM_SECONDS)` dans `_generate_under_budget()`, `signal.setitimer()` levant `OverflowError` à partir d'environ 9,2e9 s. Sans budget, `budget = None` et chaque appel reçoit les limites d'avant (espions de `tests/test_time_budget.py`). Vérifié en bac à sable le 2026-10-21 : `0`, `-1`, `inf`, `nan`, `soon` et une valeur vide refusés en code 2 ; `SCOBELIX_TIME_BUDGET=abc` → `error: SCOBELIX_TIME_BUDGET: not a positive number of seconds: 'abc'` ; variable réduite à des espaces : pas de budget ; `--time-budget 7` l'emporte sur la variable à 9 ; `time_budget=0`, `-1`, `inf`, `nan`, `"5"`, `True` ou `False` → `ValueError` dans l'interface Python. Couvert par `tests/test_time_budget.py` (`test_a_budget_must_be_a_positive_number_of_seconds`, `test_a_budget_too_long_for_an_alarm_sets_no_limit` : 1e10, 1e11 et 1e300 s avec `FUNCTION_TIMEOUT` nul, alarmes de 1e9 s, quatre fonctions décompilées, `test_the_option_and_the_variable`, `test_an_unusable_budget_is_a_usage_error`, `test_without_a_budget_every_step_keeps_its_own_limit`) et `tests/solgen/test_cli.py` (`test_the_budget_reaches_the_decompiler_and_the_payload`, `test_a_budget_too_long_for_an_alarm_sets_no_limit` : `--time-budget 1e10`, source imprimée avec `--combined-json` et avec `--solidity` seul). |
| **FR-ARCH-79** : réserve pour les étapes qui suivent les fonctions, accrue par les fonctions arrêtées à leur limite de temps ; découverte et fonctions bornées par le temps restant ; fonctions laissées de côté sous une seconde ; budget épuisé | `scobelix/decompiler.py` — classe `TimeBudget`, `BUDGET_RESERVE`, `BUDGET_RESERVE_MIN`, `TIME_LIMITED_RESERVE`, `MIN_FUNCTION_SECONDS`, `MIN_SLICE`, `_clock`, `_capped()`, `_vm_share()`, `simplification_deadline()`, `_decompile_with_loader()` ; `scobelix/loader.py` — `Loader.run()` | `TimeBudget.start()` fixe `deadline = _clock() + seconds` et `reserve = max(BUDGET_RESERVE_MIN, seconds * BUDGET_RESERVE)` (5 s, 10 %) ; `left_for_functions(now=None)` rend `deadline - now - reserve`. La découverte reçoit `max(left_for_functions(), MIN_SLICE)` (1 ms : la VM ne s'arrête qu'à son premier contrôle du temps, FR-DEC-29) ; pour chaque fonction, l'horloge est lue une fois (`began = _clock()`, `left = budget.left_for_functions(began)`) : `left < MIN_FUNCTION_SECONDS` (1 s) → `problems[hash] = fname`, `budget.skipped.append(hash)`, `budget.exhausted = True` et `logger.warning("%s: not decompiled, the time budget (%s s) is exhausted", …)`, sans appel de `dec()` ; sinon `ft = min(_capped(FUNCTION_TIMEOUT, left), MAX_ALARM_SECONDS)`, `vm_timeout = _vm_share(ft)` et `simplification_deadline(started, budget=ft)` (FR-ARCH-21 à FR-ARCH-23), le décorateur étant instancié à chaque fonction avec `ft` (jamais le paramètre `timeout=` de `timeout_decorator`, dont l'alarme survit à l'appel lorsque le décorateur a reçu 0). Après une fonction gardée `time_limited`, `budget.reserve += TIME_LIMITED_RESERVE * (_clock() - began)` (la moitié de sa durée) et, si `FUNCTION_TIMEOUT <= 0 or ft < FUNCTION_TIMEOUT`, `budget.exhausted = True` ; un `TimeoutInterrupt` reçu sous la même condition pose aussi `exhausted`. L'objet est rendu par `Decompilation.time_budget`.
